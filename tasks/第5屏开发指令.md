## 任务 A：纪要提炼主链路（必做）

### 1. 输入区：三种输入方式归一到「原文文本框」

分段选择器（三个按钮切换）：**粘贴文本 / 上传文档 / 上传录音**（录音为任务 B）

- **粘贴文本**：直接显示大 textarea
- **上传文档**：接受 `.txt` `.docx` `.pdf`
  - `.txt`：FileReader 直接读文本
  - `.docx`：**允许新增依赖 `mammoth`**（这是本屏唯一许可的依赖，docx→纯文本，浏览器端可用）
  - `.pdf`：**允许新增依赖 `pdfjs-dist`**。Vite 中 worker 配置用 `import PdfjsWorker from 'pdfjs-dist/build/pdf.worker.min.mjs?url'` 再 `GlobalWorkerOptions.workerSrc = PdfjsWorker`。若此路受阻，降级：PDF 入口提示「暂支持 txt/docx/粘贴文本」，不算失败
  - 解析出的文本填入同一个 textarea（用户可修正），文件名显示在框上方
- 统一交互：无论哪种来源，最终都汇入**同一个可编辑 textarea（原文区）**，然后点「提炼纪要」

### 2. 提炼链路（DeepSeek）

- **Prompt：新建 `src/prompt-meeting.txt`**，把 `prompt-会议纪要.md` 第二节「纪要提炼 System Prompt」代码块**一字不改**复制进去，`?raw` 导入。User 消息按定稿模板拼接：`以下是会议记录原文：\n{文本}\n请按铁律提炼。`
- 参数：temperature 0.3，max_tokens 1500，`response_format: {type:'json_object'}`
- 异常态 4 种兜底（无 key/加载中/HTTP 错误/JSON 解析失败），与现有屏一致

### 3. 结果展示区

提炼成功后渲染结果卡片：

- 顶部：会议标题（大字）+ 日期
- **结论区**：conclusions 逐条列表
- **待办区**：actionItems 表格/卡片，按 priority 排序（high 在前，🔴 标记），列：任务｜负责人｜截止时间；「〔负责人待确认〕〔时间待确认〕」原样显示并标橙色
- **待定问题区**：openQuestions 逐条，空则整节省略
- 操作按钮：
  1. **「一键复制成可发群纯文本」**：严格按 `prompt-会议纪要.md` 第三节模板生成（`□` 复选框、🔴 前缀、`—— 由「新人上手手册」整理` 署名原样保留），`navigator.clipboard.writeText` + 失败兜底 `execCommand('copy')`，成功后 toast 提示
  2. **「待办同步到工作台」**：把 actionItems 转写入 `odb_todos`（title=task，dueDate=deadline 是合法日期则换算否则 null，priority 映射 高/中/低，note 带「来自纪要：会议标题」），已存在相同标题且未完成的跳过，完成后 toast「已同步 X 条，跳过重复 Y 条」并 `logActivity('meeting-sync', ...)`

### 4. 历史纪要（供第 6 屏周报引用）

- 提炼成功即自动存入 `odb_meetings`：`{id, title, date, conclusions, actionItems, openQuestions, createdAt}`，按时间倒序**只保留最近 20 条**
- 屏幕下方「最近纪要」列表：标题 + 日期 + 待办条数，点击展开查看（复用结果渲染函数）；每条可删除

## 任务 B：录音转写链路（挑战，允许降级）

### 技术方案（DashScope WebSocket 实时识别）

纯前端无服务器，录音文件转写采用**本地解码 + WebSocket 分片推流**：

1. 前端校验：mp3/wav/m4a，≤50MB
2. `AudioContext.decodeAudioData` 解码 → 重采样为 16kHz 单声道 PCM16
3. 连接 DashScope WebSocket：`wss://dashscope.aliyuncs.com/api-ws/v1/inference`，模型 `paraformer-realtime-v2`，Header 鉴权 `Authorization: Bearer ${VITE_DASHSCOPE_API_KEY}`
4. 按 100ms 一帧二进制分片依序发送，发送完毕发 JSON `{action:'finish-task'}`
5. 收到的识别文本拼接（增量 result 文本按 sentence 顺序拼接，处理 `sentence_end` 标记），完成后填入原文 textarea
6. **loading 必须分阶段反馈**：「上传中→解码中→转写中（已 X 秒）」，禁止无反馈死等；超 30 秒音频提示「预计耗时约 X 秒」

### 环境变量

- `.env` / `.env.example` 新增一行：`VITE_DASHSCOPE_API_KEY=你的百炼key`（注意 Vite 的 VITE_ 前缀，DeepSeek 的 key 也应已是 VITE_ 前缀，对照检查 `.env.example` 模板同步更新）

### 降级判据

出现以下任一情况，直接降级：录音入口按钮置灰 + 文案「录音转写即将上线，可先粘贴文字或上传文档」：
- WebSocket 接口报 401/403 且排查 key 无效
- 分片协议调不通、识别结果为空超过 2 次尝试

**降级不算任务失败**——任务 A 跑通即本屏合格。降级时在交付说明里写清卡点，方便后续单独攻关。
