## 三、第 7 屏：新人开挂室

### 3.1 页面结构

替换 `#screen-7` 占位内容。参照第 6 屏 `rep-tabs` 的 tab 样式（类名避免与现有冲突，用 `open-tabs` / `open-tab` 前缀）做两个子标签：

1. **充电区 · 新人书单**
2. **破局区 · 新人困境**

### 3.2 书单 tab

**① 默认排序（回答"先看哪本"）**
- 排序键依次：`priority`（P0 → P1 → P2）→ `readingStage`（入职前 → 入职1个月 → 入职3个月）→ `title`
- 顶部一行小字说明排序逻辑（如「按必读优先级排序 · P0 入职前先看」），文案克制

**② 筛选（可叠加）**
- 岗位筛选下拉：从 `forRoles` 去重汇总，首项「全部岗位」；选中后只显示 `forRoles` 含该岗位 **或** 含「全部」的书
- 阅读阶段筛选：全部 / 入职前 / 入职1个月 / 入职3个月（单选项按钮组）
- 两个条件 **AND** 叠加；筛选后若无结果，显示空态文案（如「这个组合暂时没有推荐，放宽筛选看看」）

**③ 藏书票卡片**
- 书名 + 作者文字排版成"封面"：书名大字（标题化）、作者小字、左上角 `category` 类别小字，整体如藏书票/书签质感。**纯 CSS 排版，不引入任何图片资源**
- 3-5 列自适应错落布局：桌面端用 CSS `columns` 或 flex + 每张卡片不同 `margin-top`（如第 2、4 张下沉 16px）制造错落感；**≤768px 降为 2 列，≤480px 降为 1 列**
- 卡片左上角一枚圆点标记阅读状态（书签位）：想读=灰/描边、在读=主题色实心、已读=实心打钩（可用 CSS 画，不用图标库）。**点击圆点循环切换** want → reading → read → want，状态即时刷新

**④ 阅读状态持久化（重要，防坑）**
- 阅读状态存 localStorage：`odb_book_status` = `{ "b01": "reading", ... }`
- `books.json` 的 `status` 字段只是默认值，**严禁**把用户点击写回 books.json（内容配置化原则：数据文件是只读配置）
- 状态判断：localStorage 有该 id 用 localStorage 值，没有才用 JSON 默认值

**⑤ 抽屉详情**
- 点击卡片任意处（圆点除外）弹出右侧抽屉（移动端改为底部弹出）：推荐理由 `reason`、标签行（category / priority 徽标 / forRoles / readingStage）、「在线搜索」按钮
- 在线搜索按钮打开新标签页：`https://search.douban.com/book/subject_search?search_text=${encodeURIComponent(title)}`
- 抽屉带遮罩，点遮罩或右上角 × 关闭，CSS transition 动画（不用动画库）

### 3.3 困境 tab

**① 入口**
- 顶部输入框（placeholder 如「说说你现在遇到的困境…」）+ 下方高频困境标签组
- **标签组列出全部 16 条 title**，一行放不下换行（胶囊样式）；点击标签即选中该条
- 输入框支持关键词匹配：输入后按「标题包含输入文字」匹配（本地匹配，**不调任何 AI 接口**）；多条命中时展示匹配列表供点选；无命中显示提示（如「没找到完全匹配的，试试点上面的标签，或换几个关键词」）

**② 解法展示**
- 选中困境后展示：标题 + 三栏解法卡片**并排**（桌面端三列，≤768px 堆叠为上下）
- 三栏固定顺序与 JSON `style` 字段严格一致：**强硬 / 迂回 / 共赢**，栏首大字标注风格名，栏内依次渲染：
  - `say`：怎么说（加引号呈现，突出）
  - `do`：怎么做
  - `scene`：适用场景（小字弱化）
  - `caution`：分寸提醒（末尾一句，可用细线分隔或小字带 ⚠ 前缀，不喧宾夺主）
- 内容**逐字段渲染自 dilemmas.json**，禁止 AI 改写、禁止自行增删字段

**③ 收藏**
- 每张解法卡片右上角 ☆ 收藏按钮；收藏状态存 `odb_dilemma_fav`（存困境 `id` 数组）
- 已收藏的困境在标签组里带 ☆ 标记；「只看已收藏」筛选开关（默认关）
- 收藏与标签选择联动：点收藏不改变当前展示

### 3.4 第 7 屏防坑清单（必须逐条落实）

1. 阅读状态只写 `odb_book_status`，**不碰 books.json**
2. 三栏顺序死磕 JSON：强硬 → 迂回 → 共赢，不得按自己的喜好换序
3. 困境匹配纯本地，不调 DeepSeek（本屏不是 AI 核心屏，别自作主张加 AI 能力）
4. 不装任何新依赖；藏书票封面、圆点状态、抽屉全用 CSS/原生 JS 实现
5. 新增 localStorage key 统一 `odb_` 前缀，注释说明结构
6. 深浅色模式：新加的 tab、卡片、抽屉、胶囊标签全部适配 `prefers-color-scheme`（与现有第 3-6 屏做法一致，深色下无死黑死白）
7. 移动端：书单 1-2 列、三栏解法堆叠、抽屉变底部弹出、点击区域 ≥ 40px 触控友好
8. 本屏是导航锚点「成长」的目标屏，完成后确认导航高亮/滚动定位正常

## 四、第 8 屏：关于 & 初衷

### 4.1 页面结构

替换 `#screen-8` 占位。极简、居中、大量留白，自上而下三块：

**① 创作初衷**（标题两侧细线点缀）
- 标题：「关于这个手册」或更简的表达（拟一版给我过目）
- 正文（用户原话，一字不改）：
  > 我是一个大四学生，经历了"拿到 offer 却不知道怎么干活"的慌，不想让和我一样的人再经历。

**② 使用小贴士**（3-4 条）
- 拟写 3-4 条短句贴士（如「先拆一个岗位，看懂真实工作地图」「遇到困境别硬扛，试试三套解法」「每周五生成周报，让数据替你说话」——仅供参考，你来拟更好的）
- 每条一行，前置小图标（CSS/字符实现，不用图标库）

**③ 一句收尾**（底部细线分隔）
- 候选句：「你已经比昨天的自己更接近会干活了」
- 可微调语气，但保留"比昨天的自己更接近会干活"的核心表达

### 4.2 第 8 屏防坑清单

1. 文案基调：理性克制、干练温暖有力量，**不鸡汤、不煽情、不用感叹号轰炸**（感叹号全屏最多 0 个）
2. 所有用户可见文案（标题、小贴士、收尾句）在验收清单里**逐字列出**，供用户过目确认（CLAUDE.md 明确要求）
3. 深浅色适配、移动端适配（小贴士单列换行）
4. 不引入任何依赖、不做动画特效，克制是唯一要求
