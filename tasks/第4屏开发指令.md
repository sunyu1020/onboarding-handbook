## 本次任务：第 4 屏「项目台账」

### 1. 顶部：粘贴工作清单 → AI 整理（本屏 AI 核心）

- textarea 粘贴任意杂乱工作清单文本（项目名大小写不一、日期格式混乱、重复条目），点击「整理」
- 调用 DeepSeek API 整理为结构化项目条目，**先回显可编辑 → 用户确认后才入库**（与第 2 屏解析交互一致）
- **整理 Prompt 新建文件 `src/prompt-project-parse.txt`**，用 `?raw` 导入（与 prompt-todo-parse.txt 同机制）。内容要求：
  - 每条提取：项目名（统一格式：主名+副名，去重合并同一项目的重复条目）、当前进度阶段、关键节点截止日期（YYYY-MM-DD，换算不了填 null）、负责人、风险项（文本里明确提到的；没有填空数组）
  - 进度阶段必须从阶段常量里选（见下）；文本里没明确提阶段时，按时间线索推断（新任务=第一阶段），推断不出来填第一阶段并在备注注明
  - 文本里确实没有可整理内容 → 返回空数组
  - 只输出 JSON：`{"projects":[{"name":"","stage":"","deadline":"YYYY-MM-DD或null","owner":"","risks":[]}]}`
  - 同样用 `{{TODAY}}` 占位（调用时替换为当天日期）
- 疑似重复提示：回显列表里，与已有项目（localStorage 中）名称相似度高的条目，在行尾标注「⚠ 疑似与已有项目『XX』重复」，让用户自己决定导入还是忽略。禁止 AI 静默合并
- 「试一试」按钮：填入一段含重复、格式乱的示例文本（自己编 5~6 条，含"项目a""项目A"式重复、混用 2026/8/30 和 8月30日 等日期格式）

### 2. 项目行数据结构（localStorage：`odb_projects`）

```js
{ id, name, stage, deadline, owner, risks: [], todoIds: [], createdAt, updatedAt }
// stage 取值：'plan'|'draft'|'shoot'|'v1'|'launch'（对应下方 5 阶段）
// todoIds：关联的第 2 屏待办 id 数组
```

**阶段常量**（写成一个数组常量 `PROJECT_STAGES`，加注释说明这是内容模板、以后可扩展自定义；v1 固定 5 阶段不做自定义）：
`大纲 → 脚本 → 拍摄 → 初稿 → 发布`（中文名 + key 成对定义）

### 3. 项目卡片列表

- 每行/每卡展示：项目名（大字）、进度条（5 段式，点击某段直接跳到该阶段，点击后无需确认）、关键节点日期（逾期标红「已逾期 X 天」）、负责人 tag、风险项（红色小标签列表）、关联待办汇总（「待办 2/3」= 关联的待办中已完成数/总数；有逾期关联待办时该计数标红）
- **行内操作**（不做弹窗）：删除项目（确认提示）、编辑项目名/负责人（点击文字变输入框，失焦保存）
- 已逾期或有风险项（risks 非空 或 关联待办有逾期）的行：整行浅红背景 + 左侧红条，视觉规则与第 2 屏延期卡片一致
- 空状态：引导文案 + 指向粘贴输入框

### 4. 与第 2 屏联动（"自动汇总"的落地方式）

- 顶部「从待办导入」按钮：弹出面板列出 `odb_todos` 中**未完成**的待办（带标题和截止日期），勾选后点「导入」→ 每个勾选待办生成一个新项目行（name=待办标题，deadline=待办截止日，stage 第一段，owner 空），并把该待办 id 记入新行的 `todoIds`。重复导入同一待办时给出提示「该待办已关联项目『XX』」
- 渲染关联汇总时实时读取 `odb_todos`（本地刷新即可，无需事件总线）
- 第 2 屏「延期风险」卡片点击跳 `#screen-4` 的链路已存在，不需要改第 2 屏代码

### 5. 筛选区

- 阶段 tab：全部 / 大纲 / 脚本 / 拍摄 / 初稿 / 发布（选中高亮，计数显示在该阶段的项目数）
- 负责人下拉：从现有项目的 owner 去重生成；选「全部负责人」
- 搜索框：按项目名模糊过滤
- 三个条件叠加生效
