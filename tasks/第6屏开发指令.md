## 本屏逻辑架构：数据汇总在前端，AI 负责「组织成文」

**关键分工（不许让 AI 做它不该做的事）**：
- **前端负责**：从三个 localStorage 数据源计算本周数据快照（完成/延期/风险/下周计划）
- **DeepSeek 负责**：把数据快照组织成文（周报三段式 / 向上汇报版本），并让数字说话
- AI 输入的是数据快照，输出的是文章。**AI 不许编造快照里没有的数据**（铁律，见 Prompt）

## 1. 数据快照（前端计算，核心逻辑）

写一个 `buildWeeklySnapshot()` 函数，输出结构化对象：

```js
{
  weekStart: '2026-08-24',        // 本周一日期
  today: '2026-08-30',
  completion: 72,                 // 本周完成度百分比（算法与第 2 屏卡片一致，可复用该函数）
  completed: [                    // 本周已完成待办：doneAt 在本周一 0 点之后
    { title, doneAt, project? }   // project：若该待办被某项目 todoIds 关联，附项目名
  ],
  overdue: [                      // 延期：未完成且 dueDate < 今天
    { title, dueDate, days: 3 }   // days = 逾期天数
  ],
  risks: [                        // 风险：来自 odb_projects 里 risks 非空的项目
    { project, risks: ['...'] }
  ],
  nextWeek: [                     // 下周计划：未完成且 dueDate 在下周一~下周日
    { title, dueDate, priority }
  ],
  meetings: [                     // 本周创建的纪要（createdAt 在本周）
    { title, date, actionItems: [{task, owner, deadline}] }
  ],
  projects: [                     // 本周更新过的项目（updatedAt 在本周）
    { name, stage, deadline }
  ]
}
```

- **空数据处理**：四个来源都空时，快照仍正常输出（数组为空），UI 提示「本周还没有数据，去第 2/4/5 屏填一点」并给「跳转工作台」按钮
- 周界算法：以周一为起点；`days` 计算注意跨月（用 Date 相减 / 86400000，别手搓字符串比较）

## 2. 界面结构（两个子标签）

顶部标签切换：「**生成本周周报**」/「**生成向上汇报**」

### 标签一：生成本周周报

- 顶部展示统计条（可复用第 2 屏卡片样式）：本周完成度（环形小图）+ 完成 X 项 / 延期 X 项 / 风险 X 项
- 「生成本周周报」按钮 → 调 DeepSeek → 结果回显在**可编辑 textarea** → 「复制」按钮（clipboard + 兜底 execCommand）
- 历史周报列表：按周倒序，最近 8 条（`odb_reports`），点击加载到编辑区；当前周已有报告时按钮变「重新生成」，需确认覆盖
- **周报 Prompt 新建 `src/prompt-weekly.txt`**（`?raw` 导入），内容：

```
你是为一位职场新人代写周报的助手。用户会给你一份「本周数据快照」（JSON），请基于快照写一份周报。

【铁律】
1. 三段式结构，用 Markdown 小标题：## 本周完成 / ## 延期与风险 / ## 下周计划
2. 重点用数据说话：每条尽量带数字、日期、项目名（如「完成竞品分析（8/27交付，3份）」）。快照里没有的细节不许编造、不许脑补
3. 本周完成：每条一行「做了什么（带结果数字或交付物）」，按价值从高到低排；有 meeting 里自己（或未指定负责人）的任务也归入
4. 延期与风险：逐个列「事项 + 卡在哪 + 需要谁支持」（快照里没有的原因，用「原因待补充」标注，不要编）
5. 下周计划：从 nextWeek 提取，按优先级排；没数据就写「下周重点工作待排期」
6. 口吻：平实、具体、不邀功不卖惨；总字数 200~400
7. 空数据时：输出「本周暂无已完成事项，建议先补录待办与纪要」一句话，不要硬编
```

User 消息：`本周数据快照：\n${JSON.stringify(snapshot)}\n请写周报。`
参数：temperature 0.5（周报需要一点组织性又不失事实），max_tokens 1200，`response_format: {type:'json_object'}` **不要用**——周报是 Markdown 文本，直接文本输出。若现有封装强制 JSON，走「文本放 JSON 的 text 字段」兼容方式，并在交付说明里写清

### 标签二：生成向上汇报

- 入口：基于**标签一的周报结果**（编辑区当前内容）生成，若当前无周报内容，提示「先生成周报」
- 按钮「生成向上汇报」→ 调 DeepSeek → 回显可编辑 → 「复制」
- **向上汇报 Prompt 新建 `src/prompt-upward.txt`**（`?raw` 导入），内容：

```
你是职场沟通专家。用户把一份周报原文发给你（可能是 Markdown 格式），请改写为「适合直接发给直属领导」的版本。

【铁律】
1. 结构：开头一句本周总览（带完成度数字）→ 3~5 条重点成果（每条一行，含数字/交付物）→ 一条风险或需要的支持（没有就省略）→ 结尾一句下周重点
2. 只使用周报原文里的事实，不新增任何内容；原文里「原因待补充」的地方在汇报里写「下周补上」
3. 口吻：简短、有重点、像工作群里高质量汇报，不像述职报告；不要「尊敬的领导」「感谢信任」这类废话
4. 全文字数 80~150 字
```

User 消息：`我的周报原文：\n${周报文本}\n请改写。`
参数：temperature 0.5，max_tokens 600，文本输出（同标签一的兼容方式）
